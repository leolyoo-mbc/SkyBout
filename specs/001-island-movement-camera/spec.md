## User Scenarios & Testing *(mandatory)*

### User Story 1 - 하늘섬에서 기본 이동 확인 (Priority: P1)

플레이어는 실행 직후 하나의 하늘섬 위에서 캐릭터를 확인하고 WASD로 이동하며 기본 조작감을 확인한다.

**Why this priority**: 지상 이동은 이후 전투와 섬 사이 이동의 기반이며 이번 단계의 핵심 경험이다.

**Independent Test**: 하늘섬과 플레이어가 보이는 상태에서 네 방향과 대각선 이동, 정지, 가장자리 접근을 수행한다.

**Acceptance Scenarios**:

1. **Given** 처음 실행한 상태, **When** 플레이 화면이 준비되면, **Then** 하늘섬 하나와 플레이어 한 명이 보이고 플레이어는 섬 내부의 안전한 시작 위치에 정지해 있다.
2. **Given** 이동할 여유가 있는 섬 표면, **When** W, A, S, D를 각각 누르면, **Then** 화면 기준 위, 왼쪽, 아래, 오른쪽에 대응하는 방향으로 표면을 따라 이동한다.
3. **Given** 서로 직교하는 두 방향의 키를 누른 상태, **When** 이동하면, **Then** 해당 대각선으로 이동하며 두 키를 누른다는 이유로 단일 방향보다 더 빨라지지 않는다.
4. **Given** 이동 중인 상태, **When** 모든 이동 키를 놓으면, **Then** 설정한 감속에 따라 정지하고 추가 입력 없이 계속 미끄러지지 않는다.
5. **Given** W와 S 또는 A와 D를 동시에 누른 상태, **When** 이동 방향을 결정하면, **Then** 반대 입력은 해당 축에서 상쇄되고 다른 축의 유효한 입력은 유지된다.
6. **Given** 지상 이동을 확인할 수 있는 상태, **When** 사용자가 이동 속도, 가속·감속 또는 방향 전환 반응 값을 바꾸고 다시 플레이하면, **Then** 변경한 값이 이동에 반영되어 이전 조작감과 비교할 수 있다.

### User Story 2 - 탑뷰로 이동 중 위치 파악 (Priority: P2)

플레이어는 위에서 내려다보는 시점으로 캐릭터와 주변 표면을 함께 보며 섬 어디로 이동하더라도 위치와 이동 방향을 파악한다.

**Why this priority**: 이동 결과를 지속적으로 확인하고 이후 생존 액션의 기본 시점을 검증하기 위해 필요하다.

**Independent Test**: 플레이어를 중앙과 서로 다른 네 방향 가장자리로 이동시켜 캐릭터와 주변 지형이 보이는지 확인하고, 카메라 값을 조정해 시점을 비교한다.

**Acceptance Scenarios**:

1. **Given** 플레이 화면이 준비된 상태, **When** 관찰하면, **Then** 위에서 내려다보는 시점으로 플레이어와 주변 섬 표면을 동시에 구별할 수 있다.
2. **Given** 플레이어가 섬 안을 이동하는 상태, **When** 중앙에서 각 가장자리까지 이동하면, **Then** 카메라가 플레이어를 따라가며 플레이어 전체와 인접한 표면을 계속 화면 안에 보여준다.
3. **Given** 방향을 바꾸거나 정지하는 상태, **When** 이동을 반복하면, **Then** 같은 키가 같은 화면 방향의 이동을 뜻하며 캐릭터의 위치와 진행 방향을 파악할 수 있다.
4. **Given** 카메라 추적을 확인할 수 있는 상태, **When** 사용자가 카메라 각도·거리·확대 정도 또는 추적 속도를 바꾸고 다시 플레이하면, **Then** 변경한 값이 시점에 반영되어 이전 화면과 비교할 수 있다.
5. **Given** 캐릭터가 정지해 카메라 추적도 멈춘 상태, **When** 마우스 커서를 화면의 서로 다른 위치로 옮기면, **Then** 카메라는 커서에 반응해 움직이지 않는다. 캐릭터가 이동할 때도 커서 위치는 카메라 추적에 영향을 주지 않는다.

### Edge Cases

- 네 이동 키를 모두 누르면 이동 입력이 상쇄되어 설정한 감속에 따라 정지한다. 일부 키를 놓으면 남은 유효 방향으로 이동한다.
- 대각선 이동 중 한 키를 놓으면 남은 방향으로 이동하며, 키 개수가 바뀐다는 이유로 더 빨라지지 않는다.
- 플레이 화면이 입력 초점을 잃으면 정지하고, 초점 복귀 후 새로운 이동 입력 없이 이동이 재개되지 않는다.
- 다시 실행하면 이전 종료 위치와 관계없이 동일한 안전한 시작 위치와 초기 카메라 시점으로 시작한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 실행 시 공중에 떠 있는 것으로 시각적으로 구별되는 하늘섬 하나와 조작 가능한 플레이어 한 명을 제공해야 한다. 섬 표면과 바깥 공간의 경계를 구분할 수 있어야 한다.
- **FR-002**: 플레이어는 매 실행마다 동일한 섬 내부의 안전한 위치에서 정지 상태로 시작해야 한다.
- **FR-003**: W/A/S/D는 각각 화면 기준 위/왼쪽/아래/오른쪽에 대응하는 지상 이동을 제공해야 한다.
- **FR-004**: 유효 입력에 따라 이동하고 모든 이동 입력을 해제하면 설정한 감속에 따라 정지해야 한다. 대각선 입력 자체로 단일 방향보다 더 빨라져서는 안 된다. 이동 시작·정지·방향 전환의 반응은 조정한 값에 따라야 한다.
- **FR-005**: 반대 방향 입력은 각 축에서 상쇄해야 하며 다른 축의 입력 처리를 방해해서는 안 된다.
- **FR-006**: 플레이어가 섬 표면 위에 있는 동안에는 해당 표면을 따라 지상 이동해야 한다.
- **FR-007**: 카메라는 플레이어와 주변 섬 표면을 위에서 내려다보는 시점으로 보여주어야 한다.
- **FR-008**: 카메라는 캐릭터만 추적해 중앙과 모든 가장자리에서 플레이어 전체와 인접한 섬 표면을 화면 안에 유지해야 한다. 마우스 커서 위치는 카메라의 위치·방향·확대 정도에 영향을 주지 않아야 한다.
- **FR-009**: 카메라는 같은 이동 키가 같은 화면 방향에 대응하도록 보여주어야 한다. 카메라 각도·거리·확대 정도와 추적 속도는 사용자가 조정한 값을 따라야 한다.
- **FR-010**: 플레이 화면이 입력 초점을 잃으면 이동을 중단하고 초점 복귀 후 새로운 이동 입력을 받기 전까지 정지해야 한다.
- **FR-011**: 사용자는 이동 속도, 가속·감속, 방향 전환 반응, 카메라 각도·거리·확대 정도 및 추적 속도를 조정하고 다시 플레이해 결과를 확인할 수 있어야 한다. 전용 설정 화면은 요구하지 않는다.

### Key Entities *(include if feature involves data)*

- **하늘섬**: 단일 공중 지형. 걸을 수 있는 표면, 표면 높이와 경계를 갖는다.
- **플레이어**: 사용자가 직접 움직이는 단일 캐릭터. 시작 위치, 현재 위치와 이동 방향을 갖는다.
- **탑뷰 카메라**: 플레이어와 주변 표면을 보여주는 시점. 추적 대상과 조정 가능한 각도·거리·확대 정도·추적 속도를 갖는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 실행 후 하늘섬 하나와 플레이어 한 명이 보이며, 다시 실행해도 동일한 안전한 시작 위치와 현재 설정한 초기 시점으로 시작한다.
- **SC-002**: 섬 표면 안에서 네 단일 방향과 네 대각선 방향을 모두 직접 플레이해 확인한다. 8방향 모두 올바르게 이동하고 대각선 입력 자체로 더 빨라지지 않아야 한다. 속도 비교에 필요한 측정은 개발 과정에서 확인하며 사용자에게 수동 거리 계산을 요구하지 않는다.
- **SC-003**: 입력 해제, 반대 키 조합, 네 키 동시 입력 및 다른 창으로 전환을 각각 확인한다. 입력 해제와 상쇄 시에는 설정한 감속에 따라 정지하거나 남은 유효 방향으로 이동하고, 다른 창으로 전환하면 정지하며 복귀 후 새 입력 없이 움직이지 않아야 한다.
- **SC-004**: 섬 중앙에서 서로 다른 네 방향 가장자리까지 이동하고 복귀한다. 모든 구간에서 플레이어 전체와 주변 표면이 보이고 이동 방향을 파악할 수 있어야 한다. 정지해 카메라 추적도 멈춘 상태와 이동 중인 상태에서 커서를 화면의 위·아래·왼쪽·오른쪽으로 옮겨도 커서 위치가 카메라 추적에 영향을 주지 않아야 한다.
- **SC-005**: FR-011의 각 이동·카메라 조정 항목을 서로 다른 값으로 바꿔 다시 플레이했을 때, 변경 효과를 확인하고 비교할 수 있다. 사용자는 이를 통해 원하는 이동 반응과 시점을 선택할 수 있어야 한다.

## Assumptions

- 이번 기능은 최종 게임의 지상 이동과 시점을 검증하는 단계다. 키보드를 사용하는 한 명의 로컬 플레이어를 대상으로 하며 온라인 연결은 요구하지 않는다.
- 포함 범위는 하늘섬 하나, 플레이어 하나, WASD 지상 이동과 추적형 탑뷰 카메라다. 단순한 시각 표현으로 캐릭터·표면·공중 공간을 구분할 수 있으면 충분하다.
- 온라인 대전, 여러 섬, 전투, 자기장, 승패 판정, 점프, 글라이더, 비행 높이 보정, 추락 및 낙사 탈락은 이후 단계의 범위다. 스페이스바 동작은 이번 단계에서 요구하지 않는다.
- 섬 밖 이동을 막는 제한은 요구하지 않는다. 가장자리를 넘어선 뒤의 추락·낙사 동작은 이후 단계에서 정의한다.
- 이동은 화면 기준이며 카메라는 캐릭터만 추적한다. 커서 쪽 공간을 더 보여주는 동작, 플레이 도중의 수동 카메라 회전·확대 조작과 별도 조준은 이번 범위에 포함하지 않는다. 플레이 확인을 위한 카메라 값 조정은 포함한다.
- 이동 속도, 가속·감속, 방향 전환 반응, 카메라 각도·거리·확대 정도 및 추적 속도의 수치는 지금 확정하지 않는다. 구현 시 조정 가능한 초기값을 마련하고 사용자가 직접 플레이하며 정한다. 수치 미확정은 다음 단계 진행을 막지 않는다.
- 슈퍼바이브는 지상 이동과 카메라 조작감의 참고 대상이다. 정확한 수치나 모든 기능을 동일하게 재현하는 것은 이번 단계의 완료 조건이 아니다.
- 섬 크기는 모든 방향의 이동을 표면 안에서 확인할 만큼 충분한 공간이 있도록 정한다.
- 저장소에 가져온 Unity 이동 프로토타입이 있으며, 이 프로젝트를 기반으로 진행한다. 기존 이동 코드는 `Assets/Scripts/PlayerMovement.cs`에 있다. 실행 가능한 플레이 환경과 키보드 입력이 필요하다.
- 사용자 지정 구현 제약: Unity 물리 엔진의 `Rigidbody`를 사용하는 방식을 유지해 충돌·중력을 처리한다. 구체적인 이동 제어 방법은 다음 계획 단계에서 정한다.
- 기존 프로토타입의 상세 이동 로직과 조작감은 아직 검증되지 않았다. 기존 코드를 검증한 뒤 필요한 부분을 활용·수정하며, 현재 계산식이나 수치를 확정된 요구사항으로 간주하지 않는다.
- `.specify/memory/constitution.md`는 미작성 템플릿 상태다. 확정된 프로젝트 원칙은 없으며 헌법 작성은 이번 기능 명세에 포함하지 않는다.
