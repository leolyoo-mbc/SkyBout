# Quickstart: 구현 후 플레이 확인

**Date**: 2026-10-29

이 문서는 다음 구현 단계가 끝난 뒤 사용할 검증 가이드다. 현재 프로토타입이 아래 항목을 이미 통과했다는 뜻은 아니다.

## 준비

1. Unity Hub에서 저장소 루트를 프로젝트로 연다. `ProjectSettings/ProjectVersion.txt`의 `6000.3.26f1`을 사용한다. 새 프로젝트를 만들거나 버전을 올리지 않는다.
2. 기존 `Packages/manifest.json`의 패키지를 복원하고 컴파일·임포트가 끝날 때까지 기다린다. Console에 컴파일 오류가 없어야 한다.
3. `Assets/Scenes/SampleScene.unity`를 연다. Player의 이동 컴포넌트·Rigidbody·PlayerInput, Ground 레이어/Collider, Main Camera의 추적 target을 확인한다. 세부 값은 [data-model.md](data-model.md)를 따른다.
4. 단일 하늘섬과 플레이어가 있고 경계 벽이나 위치 제한이 없는지 확인한다. 검증 중 섬 밖으로 떨어지면 Play를 종료하고 재시작한다.

## 1. 시작과 재실행 — SC-001

Play를 누르고 Game 뷰를 클릭한다. 섬 하나와 캐릭터 한 명이 안전한 위치에서 보이고 캐릭터가 정지해 있어야 한다. 이동 후 Play를 종료하고 다시 실행하면 같은 시작 위치와 저장된 카메라 설정으로 시작해야 한다.

## 2. 키보드 이동 — SC-002, SC-003

섬 내부에서 W/A/S/D와 네 대각선 방향을 각각 눌러 화면 방향이 맞는지 본다. 이웃한 두 키를 누른다고 더 빨라지지 않아야 한다. 키를 놓으면 설정한 감속에 따라 멈춰야 한다. 반대 키 두 개와 네 키를 함께 누른 뒤 일부만 놓아 남은 방향도 확인한다. 기대 동작은 [입력 계약](contracts/player-controls.md)을 따른다.

정확한 속도 비교는 아래 자동 테스트로 확인한다. 사용자가 이동 거리를 계산하거나 0.1초를 재는 작업은 하지 않는다.

## 3. 창 전환 — SC-003 / FR-010

W를 누른 상태에서 다른 창으로 전환한다. 다음 경우를 모두 확인한다.

- 다른 창에서 W를 놓고 복귀: 캐릭터가 저절로 움직이지 않는다.
- W를 계속 누른 채 복귀: 자동으로 움직이지 않는다. W를 놓고 다시 누르면 이동한다.
- 처음부터 모든 이동 키를 놓고 복귀: 다음 새 입력은 정상 동작한다.

Editor가 초점을 잃었을 때 프레임이 멈추는 것만 보고 통과로 판단하지 않는다. 복귀 후 남은 입력이 없는지까지 확인한다. Editor Game 뷰와 앱 전체 초점 동작이 구분되지 않으면 구현 단계에서 Windows Standalone으로 같은 시험을 수행한다.

## 4. 카메라 — SC-004

중앙에서 위·아래·왼쪽·오른쪽 가장자리 직전까지 이동하고 돌아온다. 몸 전체와 주변 표면이 계속 보여야 한다. 정지해 추적이 멈춘 상태와 이동 중인 상태에서 커서를 화면 네 방향으로 옮겨도 커서 때문에 시점이 바뀌지 않아야 한다. 가로세로 비율 16:9와 4:3에서 선택한 구도도 확인한다. 카메라가 물리 단계마다 떨려 보이면 interpolation과 추적 위치/갱신 순서를 점검한다.

## 5. 값 조정 — SC-005

Inspector에서 이동 속도·출발 가속·정지 감속·방향 전환 가속을 각각 바꿔 다시 플레이한다. 제동값만 바꿨을 때 정지 상태의 출발 반응이 달라지지 않아야 한다. 카메라 pitch·distance·FOV·followSharpness도 각각 변경해 구도와 추적 반응 차이를 확인한다. 필드 의미와 유효 범위는 [data-model.md](data-model.md)에 있다.

Play Mode의 변경은 종료 시 되돌아갈 수 있다. 마음에 드는 값을 적어 두거나 복사한 뒤 Play를 종료하고 Edit Mode에서 적용해 씬을 저장한다. 이 기능에 자동 설정 저장 화면은 없다.

## 6. 자동 회귀 테스트

구현 단계에서 테스트 파일이 추가된 뒤 `Window > General > Test Runner`에서 PlayMode 탭의 `SkyBout.PlayModeTests` 테스트를 실행한다. 테스트는 실제 PlayerInput의 `Player_Actions` 경로를 가상 키보드로 구동한다. Keyboard&Mouse 스킴이 요구하는 가상 마우스도 제공하고 생성한 장치·오브젝트를 정리해야 한다.

예상 결과: 출발/제동 분리, 대각선 최고 속도, 접지 전환/Y 보존, 카메라 추적/커서 독립성 테스트가 모두 통과한다. 실패하면 해당 동작을 수정한 뒤 관련 테스트를 다시 실행한다. 자동 테스트 통과만으로 실제 조작감이나 창 전환 확인을 대신하지 않는다.

Editor가 열려 있지 않고 Unity CLI가 설치된 환경에서는 저장소 루트에서 다음 명령으로도 실행할 수 있다. CLI가 없다면 위 Test Runner UI만으로 충분하다.

```powershell
unity test . --editor-version 6000.3.26f1 --mode PlayMode --output ./test-results.xml
```

열린 Editor를 닫아 CLI 실행을 강제하지 않는다. 테스트 러너가 실행을 끝내지 못한 경우 통과로 기록하지 않는다.

## 검증 기록

구현 완료 보고에는 실행한 Editor 버전, 자동 테스트 결과, 수동 SC-001~005 결과와 선택한 Inspector 값을 기록한다. 미실행 항목이나 실패 항목은 그대로 남긴다. 온라인·점프·글라이더·낙사·성능 수치 동일성은 이번 완료 조건이 아니다.

### 구현 진행 기록 — 2026-10-29

- 초기 환경: Unity 6000.3.26f1, CLI 1.0.0-beta.14. SampleScene은 Edit Mode, 일시정지 아님, 최초 씬 변경 없음, 최초 C# 컴파일 오류 없음으로 확인했다.
- 테스트 준비: SkyBout.Runtime 및 SkyBout.PlayModeTests 어셈블리 컴파일 성공. 기존 Player_Actions 자산과 가상 키보드·마우스로 실제 PlayerInput 경로를 구동했다.
- 수정 전 회귀 재현: 3개 이동 검사 중 대각선/키 상쇄는 통과, 출발/제동 결합과 물리 단계의 접지 갱신은 실패했다. 별도 초점 검사도 기존 코드에서 실패했다. 실패 증거를 확인한 뒤 이동 코드를 수정했다.
- 현재 섬: 유한한 32×32 표면과 두께 2, 표면 높이 0, 시작 위치 (0,1,0). 이동 초기값은 최고 속도 8, 가속 10, 감속 50, 방향 전환 50이며 최종 조작감 값이 아니다.
- 중간에 SampleScene 저장 팝업으로 테스트가 대기했다. 사용자 저장 후 작업 씬을 닫고 깨끗한 빈 씬에서 테스트를 실행해 해결했다.

### 최종 검증 — 2026-10-29

- Unity 6000.3.26f1 / CLI 1.0.0-beta.14. PlayMode `SkyBout.PlayModeTests`: **6개 실행, 6개 통과, 실패·건너뜀 0개**. 출발/제동 독립성, 8방향 최고 속도와 반대 키/해제, 초점 복귀 중립 처리, 접지 갱신/Y 보존, Ground 마스크 오류, 초기 카메라 배치/추적/정지·이동 중 커서 독립성을 검사했다.
- 리뷰 후 카메라 추적을 잠시 끈 상태와 잘못된 Ground 마스크에서 각각 테스트가 실패하는 것을 확인했다. 추적 복원·마스크 검사 보완 후 전체 6개가 통과했다. 가상 입력 장치가 실제 장치에 의해 바뀌지 않도록 시험용 PlayerInput의 자동 장치 전환만 끄고, 시험 종료 시 장치·씬·물리/입력 설정을 복원한다.
- SC-001: 저장된 SampleScene에서 단일 플레이어와 섬, 안전한 시작 위치 (0,1,0), 실제 Player_Actions 입력 자산, dynamic Rigidbody/중력/interpolation을 확인했다. Play 종료·재실행을 수행하고 기존 이동 스크립트 GUID 및 Build Settings의 씬 참조가 유지됨을 확인했다.
- SC-002~003: 자동 검사로 직선/대각선 최고 속도 8 및 반대 키 상쇄·키 해제 정지를 확인했다. 사용자도 실제 Game 뷰의 WASD/대각선/정지와 Windows 창 전환에서 **“모두 정상”**으로 확인했다. W를 계속 누른 채 복귀하거나 다른 창에서 놓고 복귀해도 자동 이동하지 않으며 해제·재입력으로 정상 이동하는 경우를 포함한다.
- SC-004: 실제 씬의 중앙 및 네 가장자리 직전 (X/Z ±14)에서 16:9·4:3 각각 캐릭터 Collider 전체가 화면 안에 들어오는 것을 투영 좌표로 확인했다. 중앙 1280×720 렌더 캡처에서도 몸 전체와 주변 표면을 확인했다. 사용자도 실제 이동 중 카메라를 정상으로 확인했다. 정지/이동 중 커서 독립성은 자동 검사에서 통과했다.
- SC-005: 실제 씬의 런타임 컴포넌트 값을 하나씩 바꿔 비교했다. 가속 5→10의 첫 물리 단계 속도는 0.10→0.20, 감속 10→50의 제동 후 속도는 7.8→7.0, 전환 가속 2→80의 첫 X 속도는 약 0.028→1.131이었다. 최고 속도 4/8도 각각 적용됐다. pitch 65, distance 24, FOV 75 변경 효과 및 추적 반응 2/20의 차이를 확인하고 저장된 초기값으로 복원했다.
- 경계 동작: 섬 밖 X=18에서 물리를 60단계 진행했을 때 Y≈-6.18로 추락했다. 보이지 않는 벽·높이 고정·자동 복귀는 없다. 플레이 프레임 진행도 5091→5216으로 확인해 정지 화면만 검사하지 않았다.

선택한 저장값:

| 항목 | 값 |
|---|---|
| 섬 크기 / 표면 높이 / 시작 | 32×32, 두께 2 / Y=0 / (0,1,0) |
| maxSpeed / acceleration / deceleration / turnAcceleration | 8 / 10 / 50 / 50 |
| groundCheckRadius / groundLayer / airControl | 0.2 / Ground / 0.3 (기존 호환) |
| Rigidbody mass / gravity / interpolation / 회전 잠금 | 80 / 켬 / Interpolate / X·Z |
| 카메라 pitch / distance / FOV / followSharpness | 55 / 18 / 60 / 10 |

남은 한계: 조작감 최종 수치와 슈퍼바이브 수치 동일성은 검증 대상이 아니다. Windows Standalone 빌드는 실행하지 않았으며 실제 창 전환 확인은 Unity Editor에서 사용자가 수행했다. 점프·글라이더·낙사 탈락·리스폰·온라인 플레이는 이번 범위에 포함하지 않는다. 최종값은 Edit Mode 씬에 저장돼 있으며 Play 중 조정값은 별도 저장해야 한다.
