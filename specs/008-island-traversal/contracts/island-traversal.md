# Contract: 섬 사이 이동의 사용자·씬 인터페이스

## 적용 범위

로컬 키보드 플레이어가 기존 `Assets/Scenes/SampleScene.unity`에서 사용하는 게임플레이 계약이다. HTTP/API나 신규 프로덕션 public 인터페이스는 없다. 정확한 지형 좌표와 시험 출발점은 [data-model.md](../data-model.md)를 따른다.

## 씬 계약

1. Ground(A), IslandShort(B), IslandLong(C)를 고정 배치하며 상단은 모두 Y=0이다.
2. A–B 4m 빈 공간은 비전개 점프로, B–C 14m 빈 공간은 글라이딩으로 양방향 이동 가능해야 한다. B–C 비전개 점프는 목적지 착지에 실패해야 한다.
3. Ground의 X/Z 범위 ±16과 X>16, Z≈0의 기존 낙사 통로는 유지한다.
4. 지형의 Ground 레이어·비트리거 Collider·표면 지지가 실제 충돌과 일치해야 한다. 섬 옆면과 빈 공간은 지상으로 취급하지 않는다.
5. Player와 Camera는 기존 씬 루트와 참조를 유지한다. 시작 위치 (0,1,0) 및 방향은 변경하지 않는다.

## 사용자 조작 계약

| 입력/조건 | 결과 |
| --- | --- |
| WASD | 기존 화면 기준 수평 이동과 가속·감속 |
| 지상 새 Space | 한 번 점프, 계속 유지해도 자동 전개 없음 |
| 해제 후 새 공중 Space 유지 | 글라이더 표시 및 목표 발 Y=2m 보정 |
| 글라이딩 중 WASD만 해제 | 감속하여 수평 정지, Space 유지 시 계속 비행 |
| Space 해제 | 즉시 접기·중력 복원, 목적지 위라면 자연 하강 착지 |
| 목적지 위 Space 계속 유지 | 자동 착지·자동 접기 없음 |
| 탈락 후 새 R | 최초 시작 섬의 위치/방향으로 복귀 |

글라이더 해제 후 새 공중 누름으로 재전개할 수 있지만 발이 낙사 경계 아래이면 탈락이 우선한다. 초점 상실·비활성화는 기존 유지 입력 정리 규칙을 보존한다. 방문 섬은 체크포인트가 아니다.

## 카메라 계약

- 기존 pitch 55°·거리 18·FOV 60°·추적 sharpness 10의 플레이어 추적을 유지한다. 새 자동 줌·섬 중심 추적은 없다.
- 기준 화면은 16:9 1280×720. 각 방향 출발선 직전 약 1m의 최종 접근, 비행, 착지에서 플레이어와 목적지 가까운 가장자리의 대표 지점이 화면 안에 있어야 한다. 해당 지점은 이동 축 중앙선과 목적지 가까운 가장자리의 교차점으로 정의한다.
- 대표 지점과 플레이어의 `WorldToViewportPoint`는 z>0, x/y ∈ [0.02,0.98]이어야 한다. 원경 섬 전체를 동시에 표시할 필요는 없다.
- viewport 수치만으로 틈이 실제로 보인다고 주장하지 않는다. 같은 구간의 렌더 화면으로 출발 가장자리·빈 공간·목적지 가장자리 구별을 확인하고, 사람이 이동 방향을 판단할 수 있는지 별도 기록한다.
- 배치와 화면비 검증을 생략하거나 플레이어만 보인다는 이유로 FR-008 통과로 기록하지 않는다. 다른 화면비는 별도 환경으로 기록하고 지원을 주장하려면 같은 검수를 수행한다.

## 수용 및 증거 계약

| 명세 | 필수 결과 |
| --- | --- |
| SC-001 | 초기/재시작 5회 동일 배치와 안전 지지 |
| SC-002 | 짧은 구간 방향별 5회 비전개 착지 및 후속 조작 |
| SC-003 | 긴 구간 방향별 5회 비전개 실패, 각 5회 글라이딩 착지 |
| SC-004 | 목적지 위 5회 10초 유지 후 해제 3초 이내 착지 |
| SC-005 | A→B→C→B→A 3회 입력만으로 연속 이동, 전 구간 가시성 |
| SC-006 | 실제 빈 공간 낙사·재시작·새 점프/전개 10회, 복귀 ≤2초 |
| SC-007 | 각 시도 결과와 관찰자 기록, 미검증 명시 |

현재 문서는 계획이며 위 항목의 실제 통과를 의미하지 않는다. 새 시험의 실패를 없애려고 기존 이동/탈락 단언을 약화하지 않는다.
