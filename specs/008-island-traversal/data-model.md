# Data Model: 섬 배치와 이동 검증

## 정적 섬 — 기존 Unity GameObject/Collider

새 런타임 데이터 타입은 만들지 않는다. 아래 ID는 문서/시험에서 사용하는 별칭이다. 좌표·크기는 월드 m, 회전은 identity다.

| ID | 씬 이름 | 중심 | 크기 | X 범위 | Z 범위 | 상단 Y |
| --- | --- | --- | --- | --- | --- | --- |
| A | Ground | (0,-1,0) | (32,2,32) | [-16,16] | [-16,16] | 0 |
| B | IslandShort | (0,-1,26) | (12,2,12) | [-6,6] | [20,32] | 0 |
| C | IslandLong | (26,-1,26) | (12,2,12) | [20,32] | [20,32] | 0 |

- 기존 Ground의 mesh/collider 구성을 복제하여 B/C에 적용한다. 활성 Renderer와 활성 비트리거 정적 Collider, Ground 레이어 인덱스 3을 가진다. 새 Rigidbody는 없다.
- 원래 Ground는 이름·변환·자산 참조를 유지한다. B/C는 서로 다른 씬 객체 ID를 가지며 기존 객체의 ID를 재사용하지 않는다.
- 모든 상단 Y는 시험 허용 오차 0.001m 안에서 0이다. 섬 사이에는 보이지 않는 연결 Collider가 없어야 한다.

## 이동 구간 — 테스트 정의

| 구간 | 방향 | 가장자리 간격 | 도움닫기 시작 중심 (Y=1) | 점프 출발선 | 목적지 제동 기준 |
| --- | --- | --- | --- | --- | --- |
| A→B | +Z / W | 4m | (0,1,11) | Z=15.2 | B의 Z≈25 |
| B→A | -Z / S | 4m | (0,1,25) | Z=20.8 | A의 Z≈11 |
| B→C | +X / D | 14m | (1,1,26) | X=5.2 | C의 X≈25 |
| C→B | -X / A 키 | 14m | (25,1,26) | X=20.8 | B의 X≈1 |

출발선 통과 직전/근처에 입력을 발행하되 발 중심은 출발 섬 표면 안쪽이어야 한다. 실제 점프 시작 위치와 속도를 기록하며 고정 프레임 수만으로 출발을 추측하지 않는다. 점프 시점의 수평 속도는 8±0.1m/s를 검증한다. 이 수치는 시험 전제이고 이동 성능을 변경하는 설정이 아니다.

짧은 구간에서는 점프 후 글라이더를 전개하지 않는다. 긴 구간 대비 시험은 같은 도움닫기/출발선에서 비전개 실패와 새 공중 전개 성공을 비교한다. 실패란 목적지의 실제 상단 지지를 얻지 못한 채 표면 아래로 떨어지는 것이며 단순 시간 초과만으로 성공/실패를 추정하지 않는다.

## 플레이어 상태 — 기존 상태 재사용

| 현재 상태 | 사건 | 다음 상태/결과 |
| --- | --- | --- |
| Grounded | 새 Space | Airborne, 기존 점프 |
| Grounded | 가장자리 이탈 | Airborne |
| Airborne | 새 공중 Space 유지 | Gliding, 공통 발 목표 Y=2 |
| Gliding | Space 해제/초점 상실 | Airborne, 중력 복원 |
| Airborne/Gliding | 목적지 실제 상단 지지 | Grounded, 날개 닫힘 |
| 생존 상태 | 발 Y<-10 | Eliminated, 입력 차단 |
| Eliminated | 새 R | 최초 (0,1,0)·기존 방향 복귀 후 지지 재판정 |

이 표는 기존 동작의 요약이다. 새 상태나 별도의 목적지 추적 상태를 추가하지 않는다. 섬 방문이 시작 자세를 갱신하지 않는다. 경계와 같은 Y=-10은 그 이유만으로 탈락하지 않는다.

## 목적지 착지 검증

- `Grounded`이고 발 위치의 아래 raycast가 **목적지 Collider**를 가리켜야 한다.
- 발 높이가 목적지 상단 ±0.05m, 수직 속도 절댓값 ≤0.1m/s이며 최소 5회 연속 물리 갱신 동안 지지가 유지되어야 한다.
- 이후 걷기와 새 점프가 실제 가능해야 한다. 옆면 충돌이나 출발 섬 재착지는 불합격이다.
- 시험에서 내부 상태를 읽을 때 기존 reflection 패턴을 사용하며 테스트 편의용 public setter를 만들지 않는다.

## 검증 기록 — TestResults의 산출물

`008-traversal-attempts.csv`: scenario, direction, attempt, launchPosition, launchSpeed, mode, destination, landedCollider, footHeight, elapsedGameSeconds, result, reason. 벡터/문자열 CSV escaping과 invariant 수치 형식을 사용한다.

`008-camera-*.png`: 짧은/긴 구간 양방향 출발 직전·공중·목적지 착지 화면. `008-validation.md`: 실행 환경·시험 결과 경로·인수 기준별 통과/실패/미검증·관찰자 기록·남은 문제. 사람이 확인하지 않은 관찰 항목은 미검증으로 남긴다. 계획 단계에서는 이 결과 파일을 만들지 않는다.
