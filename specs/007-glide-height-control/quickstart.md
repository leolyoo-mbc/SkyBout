## 2. 구현 후 자동 검증

새 `GlideHeightMathTests`, `GlideHeightTests`와 기존 전체 PlayMode를 실행한다. 실제 씬 검증은 `GliderSceneTests`에 확장한다. 아직 없는 클래스의 0개 수집은 성공이 아니다.

시험 fixture는 기존처럼 가상 Keyboard를 자기 입력 actions.devices에만 지정하고 `InputSystem.Update → 컨트롤러 FixedUpdate → Physics.Simulate(0.02)` 순서를 사용한다. teardown에서 장치·활성 씬·물리 및 입력 설정을 복원한다. 컨트롤러가 비활성인 동안 FixedUpdate를 강제로 호출해서는 안 된다.

실제 게임 수렴 공간 예: 목표Y=2m, 발Y=-1~5m, 섬 수평 범위 밖(X>20m 등). Space를 유지하고 낙사 경계-10m와 초기±5m/s 감속 여유를 확보한다. 독립 fixture는 원점 목표0을 명시해 같은 상대 오프셋을 시험한다. 시험 배치 이동과 기능 이동을 구분한다.

**관측 주의**:

- 전개 요청 처리 전후 동일 시점의 위치 차이가 0.001m 이하인지 확인한다. 첫 보정 틱 속도 차이는 최대 가속도 ×0.02초 이하여야 한다. 이후 물리 적분에 의한 이동은 정상이다.
- 안정 구간은 처음 ±0.1m에 들어간 뒤 다시 나가지 않는 시점부터 10초로 측정하고 해당 시점이 전개 후 5초 이내인지 판정한다.
- 속도 연속성과 가속도 한도는 비충돌 구간에서 측정한다. 충돌 해결 속도 변화·재시작 위치 초기화를 보정 불연속으로 오판하지 않는다.
- 목표 통과는 단순 부호 변화 수가 아니라 반대편 0.1m 밖으로 진입하는 횟수로 센다. 작은 수치 오차를 반복 출렁임으로 집계하지 않는다.
- Space 유지 중 목표 높이 체공은 정상이며, 해제하면 중력으로 낙하한다. 최신 실제 씬10회 반복은 Space 해제로 자연 낙사하며 강제 경계 배치가 아니다. 경계 우선순위 단위 시험의 시험 배치는 별도로 유지한다.

### 선택적 배치 실행

열린 Editor와 같은 프로젝트를 동시에 배치 실행하지 않는다. 사람이 Editor를 종료한 뒤 설치 경로를 확인하여 실행한다. 렌더 검증은 이 비시각 실행으로 대체하지 않는다.

```powershell
$root = 'E:\projects\SkyBout'
$unity = 'C:\Program Files\Unity\Hub\Editor\6000.3.26f1\Editor\Unity.exe'
New-Item -ItemType Directory -Force -Path "$root\TestResults" | Out-Null
& $unity -batchmode -nographics -projectPath $root `
  -runTests -testPlatform PlayMode `
  -testResults "$root\TestResults\007-final.xml" `
  -logFile "$root\TestResults\007-final.log"
```

종료 코드뿐 아니라 실제 결과 XML의 시험 수와 실패/건너뜀을 확인한다. 이번 구현 검증은 열린 Editor의 MCP 시험 도구로 수행했으며 위 배치 명령은 실행하지 않았다. 실제 씬 반복 시험은 회차별10초 체공을 포함하므로 testcase 전체 제한300초를 사용하고 수렴/착지/재시작 판정 시간은 그대로 유지한다.

## 3. 실제 SampleScene 검수

1. Game 뷰에 초점을 두고 이동·지상 점프·키 유지 및 해제 후 공중 전개를 확인한다.
2. 섬 밖 낮은 발 높이에서 전개하여 상승하고 높은 곳에서 전개하여 하강하는지 확인한다. 위치 튐·급격한 꺾임·목표 부근 반복 출렁임이 없어야 한다.
3. Space를 누른 채 WASD만 놓아도2m에10초 머무는지 관찰한다. Space를 놓으면 날개가 닫히고 낙하해야 하며 WASD는 계속 작동해야 한다. 다시 공중 Space를 누르면 같은2m 목표로 재전개해야 한다.
4. 실제 섬 위에서 Space를 해제하여 낙하/실제 착지하고 새 점프가 가능한지 확인한다. 목표2m에서 Space 유지 중에는 착지하지 않고 떠 있는 것이 정상이다. 옆면 접촉은 착지가 아니다.
5. 초점 상실 및 컴포넌트/전체 Player 비활성화 후 복귀를 각각 시험한다. 정지된 전체 GameObject의 비활성 구간을 비행 진행 시간으로 계산하지 않는다.
6. 비전개 추락으로 탈락 후 R 재시작하고 새 전개까지 반복한다. 이전 입력·날개·수직 움직임이 남지 않아야 한다.
7. 작은 Game 뷰에서 기존 표시·안내와 카메라, 실제 높이 변화의 자연스러움을 사람이 확인한다. 검수자·뷰 크기·의견을 기록한다.

## 4. 증거와 완료 판정

`TestResults/007-*`에 기준선·변경 후 전체 시험 결과, 환경/시간, 틱별 위치·속도 및 도달 시간, 실제 씬 화면, 사람 검수 결과를 분리 기록한다. 자동 수학 시험, Unity 물리 시험, 실제 씬 렌더, 사람 검수를 혼동하지 않는다. 각 SC를 `통과 / 실패 / 미검증`으로 기록하며 차단 사유를 남긴다. 006의 미완료 사람 검수도 이번 자동 결과로 완료 처리하지 않는다.
