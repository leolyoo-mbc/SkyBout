# Data Model: 목표 비행 높이 보정

## 1. 비행 설정 — PlayerMovement 직렬화

| 필드 | 단위/기본값 | 검증/의미 |
| --- | --- | --- |
| `glideTargetFootHeight` | 월드 발 Y, 2m | 유한, `fallDeathHeight`보다 큼. 전개 위치/지형과 독립 |
| `glideHeightResponse` | s⁻¹, 3 | 양의 유한값, 제곱 및 두 배도 양의 유한값 |
| `glideVerticalAcceleration` | m/s², 10 | 유한, 0 초과 10 이하. 한 틱 보정 속도 변화 상한 |
| `fallDeathHeight` | 기존 -10m | 기존 엄격한 미만 비교 유지 |

`glideDescentSpeed`는 폐기한다. 새 필드로 이름만 바꾸어 이전 값 2를 매핑하지 않는다. 기존 씬 Player에 새 설정을 명시하고 나머지 씬 구성은 보존한다. 잘못된 설정은 기존 오류/비활성화 경로를 사용한다. Inspector 튜닝 시 수렴 검수를 다시 수행한다.

목표 ±0.1m는 **시험 판정 범위**이지 접지 기준이나 런타임 위치 스냅 범위가 아니다. 5초 수렴·10초 유지도 런타임 타이머/비행 제한이 아니라 검수 기준이다.

## 2. 파생 비행 값 — 저장 없음

| 값 | 출처/관계 |
| --- | --- |
| 현재 발 위치 | 기존 `FootPosition = body.position + (feet.position - transform.position)` |
| 높이 오차 | 목표 발 Y - 현재 발 Y |
| 현재 Y속도 | 물리 충돌까지 반영된 `Rigidbody.linearVelocity.y` |
| 보정 가속도 | 응답² × 오차 - 2 × 응답 × 현재 Y속도, ±최대 가속도로 제한 |
| 다음 Y속도 | 현재 Y속도 + 보정 가속도 × fixedDeltaTime |

`MovementMath.CalculateGlideVerticalVelocity`는 현재 발 높이, 목표, 실제 속도, 응답, 최대 가속도, deltaTime을 받고 다음 Y속도 하나를 반환한다. 입력 유효성은 소유 컨트롤러가 보장한다. 위치를 쓰거나 객체/시간/상태를 저장하지 않는다. 수평 계산 함수는 현재처럼 Y를 보존한다.

따라서 별도의 수직 속도 캐시·누적 가속도·목표 캡처·전개 시간·도달 상태 플래그가 필요 없다. 상승/하강/안정은 오차와 실제 속도의 관측값이며 새로운 FSM 상태가 아니다.

## 3. 플레이어 상태 — 기존 enum 유지

| 상태 | 수직 규칙 | 전이 |
| --- | --- | --- |
| Grounded | 기존 지상 물리, 보정 없음 | 새 지상 Space→Airborne, 지지 상실→Airborne |
| Airborne | 기존 중력·점프·추락 | 새 유효 공중 Space→Gliding, 착지→Grounded |
| Gliding | 유효 Space 유지 중 중력 꺼짐·목표 보정 | Space 해제/입력 경계→Airborne, 실제 하강 착지→Grounded, 발이 낙사 경계 미만→Eliminated |
| Eliminated | 보정/조작 금지, 기존 탈락 물리·안내 | 유효 새 R→최초 자세의 Airborne→접지 |

탈락 검사가 다른 전이보다 우선한다. 경계와 같은 발 높이는 그 이유만으로 탈락하지 않지만 이후 감속 중 경계 아래로 진입하면 탈락한다. 이미 탈락한 플레이어는 전개/보정으로 구제하지 않는다.

## 4. 물리 갱신 순서

1. 실제 발 높이가 경계 미만인지 확인하고 새 탈락이면 요청·전개를 정리 후 반환.
2. 탈락 상태라면 기존 새 R/초점 조건으로 재시작 또는 조작 차단 후 반환.
3. 기존 실제 지지로 Grounded 갱신. 착지는 목표 도달보다 우선.
4. 기존 jumpRequested를 한 번 소비. 지상 의도를 공중 전개로 바꾸지 않음.
5. glideRequested를 한 번 소비. 유효 Airborne만 전개.
6. 유효 유지 입력이 없는 Gliding은 취소한다. 유효 Space 유지 중 Gliding이면 실제 속도로 Y보정을 계산한다. 전개/접기 시 별도 위치/속도 초기화는 없다.
7. 기존 CanMove 검사 및 수평 이동. 수평 계산은 적용한 Y를 보존.
8. Unity 물리 충돌 해결 후 실제 지지 접촉을 수집. 하강 착지한 글라이더는 기존 콜백에서 즉시 닫힘.

충돌 해결로 속도가 달라지면 다음 틱 계산에 그대로 반영한다. 천장/옆면은 별도 착지 판정을 만들지 않는다.

## 5. 생명주기와 소유권

- 상태·목표 설정·중력·날개는 `PlayerMovement` 하나가 소유한다. `SetState`가 중력/표시를 갱신한다.
- Space 해제: 유지 입력과 glideRequested를 취소하고 Gliding→Airborne, 날개 끔·중력 복원. jumpRequested는 보존하여 짧은 지상 점프 탭을 누락하지 않는다.
- 초점 상실: 요청/유지/수평 입력 정리, 전개 종료. 진행 중인 물리는 중력으로 계속된다.
- 컴포넌트 비활성: 전개 종료·중력 복원, 요청/접촉/수평 정리. 동적 몸체의 중력/충돌 물리 진행, 접지/낙사 재구축은 복귀 시 수행한다.
- 전체 Player 비활성: 전개 종료, 몸체도 비활성이므로 물리 진행 없음. 재활성화 시 실제 속도를 사용하며 속도 보존 여부는 가정하지 않는다.
- 복귀: 기존 WakeUp과 입력 해제 정책 유지, 낙사·지지 우선 판정. 유지 키로 자동 전개하지 않으며 해제 후 새 공중 누름이 필요하다. 시간 보상/과거 속도 복원 없음.
- 착지/탈락: 이후 수직 보정 실행 중단, 기존 중력/표시 전환. 별도 보정 메모리가 없으므로 제거할 캐시 없음.
- R 재시작: 기존 위치·방향, 선형/각속도 0, 요청/접촉 초기화. 설정 목표는 그대로이며 새 전개가 과거 움직임을 물려받지 않음.
- 파괴: 기존 중력 복원·날개 제거·입력 해제를 유지.

## 6. 범위 밖 데이터

입력 리더의 `jumpHeld`는 유효한 새 누름을 받은 경우만 true이며 해제/입력 경계/탈락 시 false다. `IsJumpHeld`는 활성·초점·생존·유효 유지·실제 버튼 누름을 함께 확인한다. `JumpReleased`는 취소 경계를 전달하며 비행 속도를 저장하지 않는다.

목표 높이 UI, 플레이어별 목표 선택, 지형별 고도, 서버 동기화, 저장 파일, 연료/시간 데이터는 추가하지 않는다. 기존 카메라·입력 자산·최초 자세 데이터는 변경하지 않는다.
