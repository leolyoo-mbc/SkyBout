# Contract: 글라이딩 목표 높이와 기존 조작

## 사용자 인터페이스

- 기존 지상 새 Space는 점프, 해제 후 새 공중 Space는 전개다. 공중 전개가 추가 점프로 바뀌지 않는다.
- 공중 Space를 누르는 동안만 전개하며 해제하면 접기·중력 복원·높이 보정 중단이다. 해제 후 새 공중 누름으로 재전개한다. 목표 재설정·추가 점프·착지 후 예약 점프는 없다. 물리 갱신 전에 해제된 공중 탭은 전개를 예약하지 않는다.
- WASD는 기존 화면 기준 이동·속도·가감속·대각선 제한을 유지한다. Space를 유지한 채 WASD만 놓으면 수평 감속 후 정지하지만 높이 보정은 계속된다. Space만 놓아도 WASD 조작은 유지된다.
- 낮으면 상승, 높으면 하강, 목표 부근에서는 감속해 머문다. 목표는 전개 위치·수평 이동·지형과 독립이다.
- 실제 하강 착지는 보정을 종료하고 날개를 닫는다. 탈락은 모든 보정에 우선한다. 기존 안내·새 R 복귀를 유지한다.

## Inspector 인터페이스

| 설정 | 기본값 | 계약 |
| --- | --- | --- |
| `glideTargetFootHeight` | 2m | 발 위치의 월드 Y. 유한, 낙사 높이보다 엄격히 큼. 현재 섬 표면0/점프2와 같은 높이 |
| `glideHeightResponse` | 3s⁻¹ | 양의 유한값, 제곱·두 배도 유효. 높이 접근과 감쇠 응답 |
| `glideVerticalAcceleration` | 10m/s² | 유한, 0 초과 10 이하. 보정으로 바꾸는 Y속도의 시간당 상한 |

`glideDescentSpeed=2`는 삭제 대상이며 새 높이에 자동 변환하지 않는다. `Awake` 및 실행 중 `OnValidate`에서 검사하고 무효 설정은 오류 후 컨트롤러를 비활성화한다. 필수 참조·기존 수평/점프 설정·중력/몸체 검증도 보존한다. 낮춘 가속도나 변경한 응답이 기본 검수 시간에 자동 적합하다는 보장은 없으며 다시 검증한다.

## 내부 계산 경계

`MovementMath.CalculateGlideVerticalVelocity(currentFootHeight, targetFootHeight, currentVerticalVelocity, response, maxAcceleration, deltaTime) → float`

- 호출자는 유효한 설정과 양의 유한 deltaTime을 전달한다.
- 다음 Y속도만 반환하는 결정적 순수 계산이며 입력/씬/Rigidbody/시간을 직접 읽지 않는다.
- 오차 `e`, 응답 `w`, 실제 속도 `v`에 대해 `a=clamp(w²e-2wv, ±maxAcceleration)`, 결과 `v+a*deltaTime`.
- 숨겨진 적분 상태·목표 캡처·도달 타이머 없음. 실제 속도 자체를 즉시 clamp하거나 높이를 스냅하지 않는다.
- `PlayerMovement`만 반환값을 Rigidbody Y에 적용하며 기존 X/Z를 보존한다. 이후 수평 계산도 Y를 보존한다.

## 수직 연속성/충돌 계약

1. 전개로 위치나 Y속도를 별도 초기화하지 않는다. 첫 일반 보정 틱의 변화는 최대 `aMax*fixedDeltaTime`이다.
   접기도 위치나 Y속도를 초기화하지 않는다. 중력이 복원되므로 상승 중 떼면 관성으로 잠깐 더 올라갈 수 있고 이후 내려간다.
2. 기본 0.02초 틱에서 Y속도 변화 최대 0.2m/s, 비충돌 0.1초 구간 최대 1m/s다. 수치 단언에는 작은 부동소수점 오차만 허용한다.
3. 대상 시험 범위는 명세 SC-001~SC-003이다. 그 범위를 벗어나거나 장애물이 막으면 5초 수렴을 보장하지 않는다. 빠른 속도에서 한 번 지나친 뒤 복귀하는 것은 허용 범위 내에서 정상이다.
4. 목표 ±0.1m 진입은 비행 높이 도달이지 착지가 아니다. 실제 지지 접촉만 Grounded로 전환하며 속도 0/높이 근접으로 대체하지 않는다.
5. 기존 동적 충돌을 유지한다. 천장·옆면 접촉 시 관통하지 않고, 막힌 동안 수렴 시한은 제외하며 경로가 열리면 실제 위치·속도로 계속한다.
6. 발 높이 `< fallDeathHeight`가 수직 보정보다 우선한다. 같으면 아직 탈락하지 않지만 이후 경계 아래에 내려가면 탈락한다.

## 초점과 활성 상태

| 상황 | 요구 동작 |
| --- | --- |
| Space 해제 | 전개/날개/전개 요청 취소, 중력 복원. 지상 점프 요청은 취소하지 않음 |
| 초점 상실 | 유지 입력/요청/수평 입력 정리, 전개 종료·중력 복원 |
| 컴포넌트 비활성 | 전개 종료·중력 복원. 동적 몸체는 중력/충돌 물리 진행 |
| 전체 GameObject 비활성 | 전개 종료, 몸체 비활성으로 물리 진행 없음 |
| 활성화/초점 복귀 | 과거 입력 재실행/유지 키 자동 재전개 금지. 해제 후 새 공중 누름만 허용 |
| 재시작 | 기존 최초 자세·0속도·요청 초기화. 새 전개는 동일 목표, 이전 비행 잔류 없음 |
| 파괴 | 기존 중력 복원 및 날개 닫기 |

전체 GameObject 재활성화 시 Unity의 속도 보존을 가정하지 않으며 비활성 시간을 재생하지 않는다. 실제 초점 상실로 앱 실행이 중지되면 그 시간 동안의 비행 진행도 요구하지 않는다. 수평 입력 키 해제 대기와 Space 해제는 별개의 상태이며 수평 키를 놓는 것만으로 접히지 않는다.

## 관찰과 검수

기존 `IsGliding`, `IsEliminated`, 실제 Rigidbody/발 높이와 날개 표시로 검증한다. 새 외부 API·네트워크 인터페이스·입력 액션은 없다. 자동 시험에서만 기존 reflection fixture 패턴을 사용하며 디버깅을 위한 공개 설정 변경 API를 추가하지 않는다.

실제 씬의 기본 목표는 Y=2다. 유지 중 그 높이에 떠 있는 것은 정상이며 Space 해제 후 실제 접촉으로 착지/새 점프가 가능한지 검증한다. 목표보다 높은 지지 표면에 하강 접촉한 경우에는 유지 중에도 기존 접지 판정으로 전개를 종료한다. 독립 fixture의 목표0은 좌표계/충돌 시험 조건이지 게임 기본값이 아니다.

입력 경계는 `PlayerInputReader.JumpReleased`와 `IsJumpHeld`로 전달한다. 해제/초점/비활성 신호는 현재 전개와 전개 요청만 취소하며, 짧은 지상 탭의 점프 요청은 유지한다. 전체 인수 절차는 [../quickstart.md](../quickstart.md)를 따른다.
