# Online Room Contracts

## 사용자 인터페이스

기존 `Assets/Scenes/SampleScene.unity`에 온라인 방 패널 진입 수단을 추가한다. 기존 오프라인 실행도 유지한다. 패널 입력 중에는 WASD/Space/R이 캐릭터에 전달되지 않으며, 닫거나 방 입장이 끝난 뒤 키 해제·새 입력 규칙을 적용한다.

| State | 표시 / 허용 행동 |
| --- | --- |
| Offline | 방 만들기, 코드 입력/참가, 오프라인으로 돌아가기 |
| Initializing/Creating/Joining | 진행 안내, 추가 생성·참가 차단 |
| InRoom | 코드, 인원 1/2 또는 2/2, 방장/참가자 역할, 나가기 |
| Leaving | 정리 중, 새 요청 차단 |
| Failed | 원인별 메시지. 정리 완료 시 생성/참가 재시도, 정리 지연 시 연결 확인·복구 재시도·오프라인 복귀 |

코드는 앞뒤 공백 제거와 영문 대소문자 정규화 후 사용한다. 서비스가 발급하는 코드 길이/문자 규칙을 설치된 SDK와 대조하며 자체 추측 형식을 강제하지 않는다. 상세 예외는 진단 로그에 기록하되 인증 토큰은 기록하지 않는다.

## 애플리케이션 경계 (계획한 인터페이스)

- `IRoomService`: 초기화/익명 로그인, 최대 2인 방 생성, 코드 참가, 참가자 나가기, 방장 세션 삭제. 서비스 예외를 분류된 결과로 변환한다. 테스트에서는 fake로 대체한다.
- `OnlineRoomController`: 위 상태 머신과 요청 세대·30초 제한·롤백의 단일 소유자. 서비스 상태와 게임 연결 상태를 합성한다.
- `NetworkPlayer`: 네트워크 소유권에 따라 `PlayerMovement`의 로컬 조작 권한과 원격 상태 표현을 제어한다.
- `OnlineRoomBootstrap`: 씬 원본 플레이어/카메라/온라인 prefab/두 스폰 지점을 연결한다. 방 진입 전 오프라인 캐릭터를 비활성화하고 퇴장 정리 후 복원한다.

## 게임 연결 승인

1. 동일 프로토콜·맵 버전과 유효한 방 상태를 확인한다. 인증 토큰을 임의의 접속 payload에 복사하지 않는다.
2. 호스트가 접속 대기 포함 최대 2자리를 직렬로 예약한다. 세 번째 접속은 Full로 거절한다.
3. 호스트는 슬롯 위치를 정한 뒤 플레이어를 생성한다. 생성된 뒤 이동시켜 잘못된 재시작 위치를 저장하지 않는다.
4. 연결당 플레이어 정확히 한 개. 스폰 실패·연결 끊김 시 객체 제거와 슬롯 반환은 멱등적이다.
5. 연결 승인 완료와 로컬 플레이어 준비 이전에는 성공을 표시하지 않는다.

## 복제·소유권

- Transform은 소유자 권한, 지속 상태는 소유자 쓰기/모두 읽기. 서버/호스트만 객체 생성·제거를 결정한다.
- 호스트에서 참가자 복제본도 원격으로 취급한다. `IsServer`를 입력 권한으로 사용하지 않는다.
- 지속 상태 초기 수신 후 원격 날개를 즉시 반영한다. OnValueChanged만 기다려 늦은 참가자에게 기본 상태를 보이지 않는다.
- 재시작은 자기 위치·속도·입력 요청·전개 상태를 초기화하고 다른 캐릭터를 건드리지 않는다. 원격 화면에서도 텔레포트로 처리한다.
- `Awake/OnEnable`은 네트워크 스폰보다 먼저 실행될 수 있다. prefab은 기본 입력 비활성으로 작성하고 소유권 확정 전에는 구독하지 않는다. 원격 Rigidbody를 kinematic으로 바꾼 뒤 기존 동적 물리 검증이 실행되지 않도록 생명주기를 분리한다.

## 종료·장애

- 정상 참가자 퇴장: 서비스 멤버십 제거, 자기 연결 종료, 호스트 캐릭터 제거/슬롯 반환. 기존 코드는 유지한다.
- 참가자 비정상 끊김: 호스트가 해당 서비스 멤버도 명시 제거한다. 서비스 기본 120초 제거에 의존하지 않는다. 연결 ID→인증 멤버 매핑은 SDK가 확인한 멤버와 연결을 대조하며, 클라이언트가 임의 지정한 다른 멤버를 제거하지 않는다.
- 정상 방장 퇴장: 방 닫기/삭제, 참가자 종료 안내, 네트워크 종료. 자동 방장 이전을 사용하지 않는다.
- MPS가 서비스 호스트를 자동 선출하더라도 NGO 게임을 재개하지 않는다. 새 서비스 호스트가 된 잔여 참가자는 방 삭제 후 메뉴로 돌아간다.
- 비정상 종료: transport 연결 감지 30초 이하를 실제 빌드에서 검증한다. 끊김 확정 후 5초 이내 로컬 인원·캐릭터·안내를 반영한다.
- 서비스 목록에만 남은 죽은 방은 게임 연결 성공으로 취급하지 않는다. 잘못된 코드/종료된 방은 NotFoundOrClosed로 분류하고 동일하게 “코드가 잘못되었거나 종료된 방입니다”를 표시한다. 빈 입력은 InvalidCode로 구별해 코드 입력을 안내한다.
- 타임아웃은 `Task.WhenAny`만으로 완료 처리를 끝내지 않는다. 늦게 완료된 서비스 작업도 관찰·정리하며 새 요청과 연결 객체를 공유하여 종료하지 않는다.
- 요청 시작 후 30초 안에 성공/실패를 표시한다. 실패 후 정리 표시는 추가 30초까지만 허용하고 이후 복구 안내로 바꾼다. 복구 재시도 한 번도 30초 안에 결과를 알린다. 이전 작업과 원격 멤버십 정리가 확인되기 전에는 새 생성/참가를 시작하지 않는다. 서비스 장애 중 즉시 원격 자리 삭제를 보장하지 않는다.
- 복구 안내에서 오프라인 복귀를 허용한다. 로컬 네트워크 객체·입력·카메라를 정리한 뒤 원본을 복원하며 원격 작업 완료를 기다려 오프라인 복귀를 막지 않는다. 늦은 결과 정리 책임은 유지하고 오프라인 상태에서도 미정리 요청이 있으면 새 온라인 접속만 차단한다.
