# Feature Specification: 탈락 후 재시작

**Feature Branch**: `main` (브랜치 생성 훅 없음, 현재 브랜치 유지)

**Created**: 2026-10-30

**Status**: Draft — 범위 확정, 계획 수립 준비 완료

**Input**: User description: "혼자 반복해서 시험할 수 있도록 탈락 후 재시작 기능 구현." 범위 확인에서 사용자가 A(4단계: 탈락 후 재시작)를 선택했다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 탈락 후 같은 섬에서 다시 시작 (Priority: P1)

플레이어는 낙사로 탈락한 뒤 게임을 종료하지 않고 다시 시작하여 이동·점프·추락을 혼자 반복 시험한다.

**Why this priority**: 실행을 종료하고 다시 켜는 과정 없이 낙사 시험을 반복하는 것이 이번 기능의 핵심 가치다.

**Independent Test**: 섬 밖으로 떨어져 탈락한 뒤 화면에 안내된 R 키를 눌러 시작 위치로 복귀하고, 이동·점프·재탈락까지 확인한다.

**Acceptance Scenarios**:

1. **Given** 낙사로 탈락한 플레이어, **When** 탈락 안내가 표시되면, **Then** 플레이어 위치가 화면 밖이어도 탈락 사실과 `R: 재시작` 안내를 확인할 수 있다.
2. **Given** 탈락 상태에서 재시작 안내를 보고 있는 플레이어, **When** R 키를 새로 누르면, **Then** 같은 섬의 최초 시작 위치에서 생존한 지상 상태로 복귀하고 탈락·재시작 안내가 사라진다.
3. **Given** 재시작을 마치고 조작하지 않는 플레이어, **When** 2초가 지나면, **Then** 이전 추락의 움직임 때문에 다시 떨어지거나 공중으로 튀지 않고 안전한 시작 위치에 머문다.
4. **Given** 재시작을 마친 플레이어, **When** WASD 이동과 지상 스페이스바 점프를 시도하면, **Then** 최초 실행과 같은 이동·점프·착지가 가능하고 기존 탑뷰 카메라로 플레이어와 주변 섬을 볼 수 있다.
5. **Given** 재시작 후 다시 섬 밖으로 이동한 플레이어, **When** 발 위치가 기존 낙사 높이보다 낮아지면, **Then** 다시 탈락하고 같은 방법으로 재시작할 수 있다.

---

### User Story 2 - 의도하지 않은 재시작 없이 반복 시험 (Priority: P2)

플레이어는 생존 중의 잘못된 입력이나 재시작 키를 길게 누르는 동작 때문에 위치가 갑자기 초기화되지 않은 채 반복 시험한다.

**Why this priority**: 시험 중 임의 초기화와 연속 재시작을 방지해야 이동·낙사 결과를 신뢰할 수 있다.

**Independent Test**: 생존 중 R 입력, 탈락 전부터 R 유지, 탈락 후 R 길게 누르기를 각각 시험하고 명시적인 새 입력에만 한 번 재시작되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 지상 또는 공중에서 생존 중인 플레이어, **When** R 키를 누르면, **Then** 위치·생존 상태가 초기화되지 않고 진행 중인 이동·점프·추락이 유지된다.
2. **Given** R 키를 누른 채 추락하는 생존 플레이어, **When** 낙사하여 탈락하면, **Then** 자동 재시작하지 않으며 R 키를 놓았다가 다시 눌러야 재시작한다.
3. **Given** 탈락한 플레이어, **When** R 키를 눌러 계속 유지하거나 빠르게 여러 번 누르면, **Then** 첫 유효 입력으로 한 번만 재시작하고 이후 생존 상태의 입력은 위치를 다시 초기화하지 않는다.
4. **Given** 탈락 상태의 플레이어, **When** WASD나 스페이스바만 입력하거나 10초간 기다리면, **Then** 탈락 상태와 안내가 유지되며 자동으로 복귀하지 않는다.

### Edge Cases

- 플레이어가 카메라 밖으로 떨어져도 안내를 읽고 R 키로 재시작할 수 있다.
- 낙사 판정과 R 입력이 같은 시점에 겹치면 탈락을 먼저 확정하고, 이후의 새 R 입력으로만 재시작한다.
- 재시작은 이전 낙하·점프 움직임과 탈락 상태를 남기지 않는다. WASD 또는 스페이스바를 놓은 상태에서는 복귀 직후 임의 이동·점프가 발생하지 않는다.
- 탈락 중 누른 스페이스바를 재시작까지 유지하더라도 저장된 입력으로 자동 점프하지 않는다. 복귀 후 지상에서 새로 누르면 점프한다. 유지 중인 WASD는 복귀 후 현재 입력대로 이동한다.
- 입력 초점을 잃었다가 복귀하는 것만으로 탈락이 해제되거나 재시작되지 않는다.
- 반복 재시작 후에도 플레이어와 탑뷰 시점이 중복되지 않고 하나의 플레이 대상으로 시험을 계속한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 낙사 탈락 시 기존 탈락 안내와 함께 `R: 재시작` 안내를 표시하고, 플레이어가 화면 밖이어도 재시작 전까지 유지해야 한다.
- **FR-002**: 시스템은 탈락이 확정된 뒤 R 키를 새로 눌렀을 때만 한 번 재시작해야 한다. 자동 재시작, 생존 중 R 입력, 탈락 전에 누른 키의 유지, 입력 초점 복귀만으로는 재시작해서는 안 된다.
- **FR-003**: 재시작 시 플레이어를 최초 실행 시의 안전한 섬 위 시작 위치와 방향으로 복귀시키고 생존한 지상 상태로 전환해야 한다.
- **FR-004**: 재시작은 이전 추락·점프의 수직 움직임과 탈락 상태를 초기화하고, 탈락·재시작 안내를 제거해야 한다. 조작하지 않으면 시작 위치에 안전하게 머물러야 한다.
- **FR-005**: 재시작 후 기존 WASD 이동, 지상 스페이스바 점프·착지 및 탑뷰 카메라를 사용할 수 있어야 한다. 카메라는 재시작 완료 시 시작 위치의 플레이어와 주변 섬을 다시 보여야 한다.
- **FR-006**: 재시작 후에도 기존 낙사 규칙을 유지해야 한다. 발 위치가 낙사 높이와 같거나 높으면 그 이유만으로 탈락하지 않고, 낮아지면 다시 탈락하여 재시작을 요청할 수 있어야 한다.
- **FR-007**: 시스템은 실행을 종료하지 않고 탈락과 재시작을 반복할 수 있어야 하며, 반복 시 플레이어 또는 플레이 시점이 중복되어서는 안 된다. 섬 배치와 이동·점프·낙사 설정은 최초 실행과 같게 유지해야 한다.
- **FR-008**: 탈락 상태에서는 기존처럼 WASD와 스페이스바의 플레이 동작을 차단해야 한다. 탈락 중 입력한 점프를 재시작 뒤 지연 실행해서는 안 되며, 복귀 후 점프는 새 스페이스바 입력을 요구해야 한다. 유지 중인 WASD는 복귀 후 현재 입력으로 처리해야 한다.
- **FR-009**: 낙사 판정과 R 입력이 같은 시점이면 탈락을 우선 확정하고 해당 입력으로 즉시 재시작해서는 안 된다. 이후 새 R 입력은 정상적으로 재시작해야 한다.

### Key Entities *(include if feature involves data)*

- **플레이어 생존 상태**: 생존 또는 탈락을 구분한다. 재시작은 탈락에서 생존으로 복귀시키는 명시적인 행동이다.
- **시작 기준**: 최초 실행 시의 안전한 섬 위 위치와 방향. 각 재시작에서 동일하게 사용한다.
- **탈락·재시작 안내**: 탈락 사실과 R 키 조작을 알려 주는 화면 정보. 탈락 동안 유지되고 재시작하면 제거된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 낙사 시험 10회 모두 탈락 후 1초 이내에 탈락·R 키 안내가 표시되며, 화면 밖으로 추락한 경우에도 읽을 수 있다. 안내된 키를 한 번 누르면 2초 이내에 같은 섬의 시작 위치에서 다시 조작할 수 있다.
- **SC-002**: 재시작 직후 모든 이동·점프 입력을 놓고 2초간 관찰하는 시험 10회 모두 시작 위치에서 안전한 지상 상태를 유지하며 이전 추락으로 인한 재탈락이나 자동 점프가 0회다.
- **SC-003**: 실행 종료 없이 `탈락 → 재시작 → 이동 → 점프·착지 → 재탈락`을 20회 연속 수행할 수 있다. 매회 재시작 후 탑뷰로 플레이어와 주변 섬을 확인할 수 있고, 중복 플레이어·중복 시점·누적 안내는 0회다.
- **SC-004**: 생존 중 R 입력, 탈락 전부터 R 유지, 탈락 후 R 길게 누르기를 각각 5회 시험해 의도하지 않은 초기화는 0회다. 탈락 후 새 R 입력은 5회 모두 한 번만 재시작한다.
- **SC-005**: 재시작 후 낙사 경계 바로 위·동일·바로 아래를 각각 5회 확인하여 위·동일에서의 오탈락은 0회, 아래에서의 탈락은 5회다. 탈락 상태에서 WASD·스페이스바만 입력하며 10초간 기다리는 시험 5회 모두 생존 복귀가 없다.
- **SC-006**: 탈락 중 스페이스바를 누른 채 재시작하는 시험과 탈락 상태에서 입력 초점을 잃었다가 복귀하는 시험을 각각 5회 수행하여 자동 점프와 의도하지 않은 재시작은 0회다. 낙사 판정과 R 입력이 겹치는 시험 5회 모두 탈락을 유지하고 이후 새 R 입력으로만 복귀한다.

## Assumptions

- 사용자가 선택한 A에 따라 이번 명세는 4단계인 탈락 후 재시작만 다룬다. 5단계 글라이더·비행 높이 보정은 포함하지 않는다.
- `specs/001-island-movement-camera/spec.md`, `specs/002-ground-jump/spec.md`, `specs/003-fall-elimination/spec.md`의 이동·카메라·점프·낙사를 선행 기반으로 삼는다. 이번 문서는 실제 구현 완료나 테스트 통과를 보증하지 않는다.
- 한 명의 로컬 키보드 플레이어와 기존 하늘섬 하나로 검증한다. 온라인 대전, 전투, 자기장, 여러 섬, 최후 생존자 판정은 범위 밖이다.
- 별도 지정이 없으므로 재시작 키는 R로 정한다. 별도 메뉴, 버튼, 확인 창, 키 변경 설정은 요구하지 않는다.
- 최초 시작 위치는 낙사 경계 위의 안전한 섬 표면에 있으며 같은 위치로 반복 복귀할 수 있다고 가정한다. 무작위 시작 위치와 중간 저장 지점은 요구하지 않는다.
- 이전 명세의 ‘게임 내 재시작 미제공’은 3단계 범위 제한이었다. 이번 기능은 이를 확장하되 낙사 높이·기존 조작 규칙은 변경하지 않는다.
- `.specify/memory/constitution.md`는 미작성 템플릿이므로 확정된 추가 프로젝트 원칙은 없다.
