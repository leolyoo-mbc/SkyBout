# Contract: 로컬 재시작 입력과 화면

## 사용자 입력 계약

| 상황 | 입력 | 보장 |
| --- | --- | --- |
| 생존 중 지상/공중 | R | 초기화하지 않고 기존 플레이 유지 |
| 탈락 확정 후, 활성·초점 있음 | R을 새로 누름 | 다음 물리 갱신에서 동일 플레이어가 최초 시작 자세로 복귀 |
| 탈락 전부터 R 유지 | 계속 유지 | 자동 재시작 없음; 해제 후 새 누름 필요 |
| 낙사 판정과 재시작 요청 겹침 | R | 새 탈락 판정 우선, 해당 요청 폐기 |
| 탈락 후 R 연타/유지 | R | 첫 유효 요청 한 번만 적용; 생존 후 추가 초기화 없음 |
| 탈락 중 | WASD, Space, 대기 | 복귀하지 않음 |
| 재시작 순간 WASD 유지 | 현재 방향 | 복귀 후 현재 Move 값으로 이동 재개 |
| 탈락부터 Space 유지 | 계속 유지 | 자동 점프 없음; 놓았다가 다시 눌러야 점프 |
| 초점 상실/복귀 | 유지 입력 | 복귀 자체로 재시작·점프 없음 |

입력은 PlayerInput의 기존 Player 맵과 SendMessages를 사용한다. `Player/Restart`는 Button이며 Keyboard&Mouse 그룹의 R 키에 연결한다. Action map을 탈락 시 비활성화하지 않는다.

## 화면 계약

- 탈락 안내는 1초 이내에 보이고 화면 밖 추락에도 유지된다.
- 탈락 사실과 `R: 재시작`에 해당하는 읽을 수 있는 안내를 함께 표시한다. 기본 폰트 제약이 있으면 `R: Restart`로 의미를 유지한다.
- 재시작 후 안내는 사라지고 2초 이내에 시작 위치에서 조작 가능해야 한다.
- 재시작이 적용된 렌더 프레임에서는 기존 탑뷰가 시작 위치의 플레이어와 주변 섬을 보여야 한다. 이전 추락 위치에서 천천히 따라오도록 방치하지 않는다.

## 런타임 연결 계약

### PlayerMovement

- 기존 `OnMove(InputValue)`, `OnJump(InputValue)`, 읽기 전용 `IsEliminated` 계약 유지.
- 추가 `OnRestart(InputValue)`는 입력 요청만 수집한다. 호출 즉시 순간이동하지 않는다.
- Start의 필수 입력 검증에 Player/Restart를 포함한다. 누락되면 명확한 오류를 기록하고 이동 컴포넌트를 비활성화한다.
- 씬의 cameraFollow 참조는 기존 Main Camera의 TopDownCameraFollow에 연결한다. 단위 테스트에서 카메라를 생략해도 물리 복귀는 가능하다.

### TopDownCameraFollow

- 추가 `public void SnapToTarget()`은 기존 target과 카메라 설정을 검증하고 즉시 배치한다.
- Start와 재시작에서 공유하며 평상시 LateUpdate 보간·시점 설정을 바꾸지 않는다.

## 호환성 및 제외

기존 입력 자산의 Move/Jump ID, 플레이어·카메라 인스턴스, 섬 배치와 물리 설정을 유지한다. 새 네트워크 API, 저장 형식, 새 씬, 별도 메뉴·키 변경 UI는 없다.
