# Player Glider Contract

HTTP·네트워크 API는 없다. 이 문서는 게임 사용자에게 노출되는 입력·피드백과 기존 Unity 씬의 설정 계약이다.

## 조작

| 상황 | 입력 | 결과 |
| --- | --- | --- |
| 실제 지지 위 생존 | 새 Space | 기존 고정 높이 점프 |
| 비전개 공중 생존 | 해제 후 새 Space | 글라이더 전개, 일정 완만 하강 |
| 글라이딩 | Space 유지/재누름 | 변화 없음; 접기·추가 점프 없음 |
| 생존 전체 | WASD / 기존 방향키 | 기존 화면 기준 수평 이동, 같은 속도·가감속·대각선 제한 |
| 탈락 | WASD / Space | 조작 차단 |
| 탈락 | 기존 조건의 새 R | 시작 위치 복귀, 비전개, 기존 카메라 스냅 |

Jump Button 액션·바인딩·ID와 생성 코드는 바꾸지 않는다. 한 번의 누름은 한 가지 의도만 만든다. 입력 시 지상 점프였지만 실행 시 섬 밖이면 점프를 버리며 전개로 바꾸지 않는다. 입력 시 전개였지만 실행 시 착지했으면 전개를 버리며 지상 점프로 바꾸지 않는다. 이미 착지 판정된 후 받은 새 입력은 지상 점프다. 공중 Space 무동작이라는 과거 요구만 이번 기능에서 대체한다.

## 물리 및 전개 피드백

- 초기 일정 하강 속도 2 m/s. 전개 순간 Y속도는 음수로 바뀌며 위치 도약·추가 상승은 없다. 수치 조정은 허용하되 양의 유한값과 느린 하강 검증을 충족한다.
- 섬 위 점프 전개 후 착지할 수 있다. 섬 밖에서는 허공 정지하지 않고 결국 낙사한다.
- 발 Y가 기존 경계보다 낮으면 입력보다 탈락을 우선한다. 경계와 같은 높이는 그 이유로 탈락하지 않는다.
- 실제 씬 Player에 `gliderVisual`을 연결한다. 뚜렷한 색의 가로 날개 모양 자식과 URP 호환 재질을 사용하며 Collider/Rigidbody는 두지 않는다. 기존 Player Collider·발 참조·Ground 레이어·카메라·섬 배치는 보존한다.
- 전개 표시를 매번 생성하지 않고 기존 자식의 활성 여부만 바꾼다. Grounded/Eliminated/재시작에서는 비표시, Gliding에서는 표시한다.
- 자동 fixture가 렌더를 검증하지 않을 때는 표시 참조를 생략할 수 있으나 실제 플레이 씬의 누락은 통합 시험 실패다. 표시 제어는 null 안전하게 하고 필수 물리 설정 검증과 분리한다.

## 생명주기

- 초점 상실·컴포넌트 비활성화는 미처리 입력·수평 움직임을 정리하되 생존 공중의 전개 여부는 유지한다. 물리 진행 중 수직 이동은 계속된다.
- 다시 활성화하면 지지·낙사부터 재검사한다. 비활성화 동안 착지했다면 계속 글라이딩하지 않고 지상으로 정리한다.
- 복귀 시 기존 실제 키 해제 확인 정책을 유지한다. 재시작 시 유지 중 WASD만 기존 정책대로 재개하고, 과거 Space는 실행하지 않는다.
- 컨트롤러 제거 시 중력이 꺼진 Rigidbody만 남지 않게 기본 중력을 복원한다.

## 호환성 및 검증 경계

새 공개 관측값 `IsGliding`은 기존 `IsEliminated`와 같은 읽기 전용 상태 조회다. 수직 속도나 내부 요청을 외부에서 조작하는 API는 제공하지 않는다. 테스트의 기존 private 필드 관측은 이름 변경 없이 유지하되 새 상태 의미에 맞는 단언만 추가한다.

렌더 피드백·조작감은 실제 Game 뷰로 확인한다. headless 상태 조회만으로 시각 계약을 통과 처리하지 않는다. 속도 비교 구간·반복 횟수·허용 오차와 실행 절차는 [quickstart.md](../quickstart.md)를 따른다.
