# Feature Specification: 플레이어 입력·상태 처리 리팩토링

**Feature Branch**: `main` (브랜치 생성 훅 없음, 현재 브랜치 유지)
**Created**: 2026-10-30
**Status**: Draft — 품질 검토 완료, 계획 수립 준비
**Input**: User description: "기존 이동·점프·낙사·재시작 동작을 유지하면서 플레이어 입력·상태 처리를 리팩토링한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기존 조작 그대로 이동하고 점프하기 (Priority: P1)

플레이어는 내부 처리 방식이 바뀐 뒤에도 기존 WASD와 스페이스바로 이동·점프·착지를 수행하고, 같은 탑뷰 시점과 조작 설정을 사용한다.

**Why this priority**: 내부 구조 개선 때문에 기존 조작을 다시 배우거나 이동·점프 결과가 달라져서는 안 된다.

**Independent Test**: 기존 섬에서 정지 점프, 8방향 이동, 이동 중 점프와 방향 변경을 수행하고 기존 설정과 결과를 비교한다.

**Acceptance Scenarios**:

1. **Given** 안전한 섬 위의 플레이어, **When** 네 방향과 네 대각선으로 이동하고 입력을 해제하거나 방향을 바꾸면, **Then** 기존 화면 기준 방향, 최고 속도, 가속·감속, 방향 전환과 대각선 속도 제한이 유지된다.
2. **Given** 발아래 걸을 수 있는 표면에 서 있는 플레이어, **When** 스페이스바를 새로 누르면, **Then** 기존 설정 높이로 한 번 점프하고 표면으로 돌아오면 착지한다.
3. **Given** 점프 중인 플레이어, **When** 스페이스바를 반복 입력하거나 착지 이후까지 유지하면, **Then** 추가 공중 점프와 자동 재점프가 발생하지 않고 착지 후 새 입력으로만 다시 점프한다.
4. **Given** 정지 또는 이동 점프 중인 플레이어, **When** WASD를 변경하거나 해제하면, **Then** 기존 수평 조작이 유지되고 탑뷰 카메라 추적과 점프 높이는 변경되지 않는다.

### User Story 2 - 같은 규칙으로 탈락하고 반복 재시작하기 (Priority: P1)

플레이어는 기존 낙사 기준으로 탈락하고, 안내된 R 키로 같은 시작 위치에 복귀하여 실행 종료 없이 시험을 반복한다.

**Why this priority**: 낙사와 재시작은 이동·점프 시험을 반복하는 핵심 흐름이며 상태 처리 변경의 회귀 위험이 높다.

**Independent Test**: 한 번의 실행에서 낙사, 안내 확인, 새 R 입력, 시작 위치 복귀, 이동·점프·착지를 연속 반복한다.

**Acceptance Scenarios**:

1. **Given** 낙사 경계 부근의 생존 플레이어, **When** 발 위치가 경계와 같거나 그 위에 있으면, **Then** 높이만을 이유로 탈락하지 않으며 경계 아래로 내려간 경우에만 탈락한다.
2. **Given** 탈락한 플레이어, **When** WASD·스페이스바를 입력하거나 기다리면, **Then** 이동·점프 조작은 차단되고 탈락 상태와 재시작 안내는 유지된다.
3. **Given** 탈락 상태에서 R 키가 해제된 플레이어, **When** R 키를 새로 누르면, **Then** 최초 위치·방향으로 복귀하고 이전 낙하·회전 움직임과 안내가 제거되며 탑뷰 시점으로 다시 조작할 수 있다.
4. **Given** 생존 중이거나 탈락 전부터 R 키를 유지한 플레이어, **When** R 입력 또는 낙사가 발생하면, **Then** 임의 초기화나 자동 재시작이 발생하지 않는다. 탈락 후 키를 해제하고 새로 누르면 한 번 재시작한다.
5. **Given** 같은 시점에 낙사와 R 입력이 발생하는 플레이어, **When** 상태가 판정되면, **Then** 탈락이 우선하고 이후 새 R 입력으로만 재시작한다.
6. **Given** 탈락 중 WASD와 스페이스바를 유지한 플레이어, **When** 유효한 R 입력으로 재시작하면, **Then** 유지 중인 이동은 재개하지만 저장된 점프는 실행하지 않으며 해제 후 새 지상 입력으로 점프할 수 있다.

### User Story 3 - 초점 전환과 조작 재개 시 오입력 방지 (Priority: P2)

플레이어는 플레이 화면을 벗어났다가 돌아오거나 플레이 대상이 비활성화된 뒤 다시 활성화되어도 이전 입력이 재실행되는 문제 없이 조작을 재개한다.

**Why this priority**: 입력 처리 교체 후에도 기존 오입력 방지 규칙과 반복 실행의 안정성이 유지되어야 한다.

**Independent Test**: 생존·공중·탈락 상태 각각에서 키를 유지한 채 초점을 전환하고, 별도로 비활성화·재활성화를 수행한 뒤 키 해제와 새 입력을 확인한다.

**Acceptance Scenarios**:

1. **Given** 이동·점프 입력 중인 생존 플레이어, **When** 플레이 화면이 초점을 잃으면, **Then** 수평 이동은 중단되고 예약된 점프는 실행되지 않는다. 이미 진행 중인 상승·하강은 플레이가 진행되는 동안 계속된다.
2. **Given** 키를 유지한 채 초점을 되찾거나 다시 활성화된 플레이어, **When** 새 입력 없이 기다리면, **Then** 이동·점프·재시작이 임의로 실행되지 않으며 기존의 키 해제 조건을 충족한 뒤 새 입력은 정상 작동한다.
3. **Given** 여러 번 비활성화·재활성화한 플레이어, **When** 지상에서 스페이스바 또는 탈락 후 R 키를 새로 누르면, **Then** 한 번의 입력에 해당 동작이 한 번만 발생한다.

### Edge Cases

- 서로 반대인 이동 키를 동시에 누르면 결과 이동량이 0이더라도 키를 모두 놓은 것으로 간주하지 않는다.
- 두 물리 갱신 사이에 점프·재시작 키를 빠르게 눌렀다 놓아도 조건을 충족한 새 입력은 한 번 처리하며, 허용되지 않은 입력은 나중에 재실행하지 않는다.
- 섬 가장자리나 옆면 접촉만으로 지상 상태가 되거나 공중 점프가 허용되어서는 안 된다.
- 재시작 직후 실제 발아래 지지를 다시 확인하며 이전 접촉 정보 때문에 허공에서 점프해서는 안 된다.
- 재시작 요청 후 초점 상실 또는 비활성화가 발생하면 해당 요청을 나중에 실행하지 않는다.
- 탈락한 플레이어가 화면 밖에 있어도 안내를 읽을 수 있어야 하며, 복귀 후 첫 표시 화면에서 안내가 남아서는 안 된다.
- 재활성화와 반복 재시작으로 입력이 중복 처리되거나 플레이어·카메라·안내가 누적되어서는 안 된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 기존 WASD 방향, 최고 속도, 가속·감속, 방향 전환, 대각선 속도 제한과 공중 수평 조작을 유지해야 한다.
- **FR-002**: 시스템은 실제 발아래 지지가 있는 지상에서 받은 새 스페이스바 입력에만 한 번 점프하고 기존 목표 높이와 착지 규칙을 유지해야 한다. 공중·옆면 접촉·키 유지·공중 입력 저장으로 추가 점프해서는 안 된다.
- **FR-003**: 시스템은 발 위치가 기존 낙사 높이보다 엄격히 낮을 때 탈락해야 하며, 탈락 중 이동·점프 조작을 차단하고 화면 밖에서도 탈락·R 키 안내를 유지해야 한다.
- **FR-004**: 시스템은 탈락 후 새 R 입력에만 한 번 재시작해야 한다. 생존 중 입력, 탈락 전부터의 키 유지, 시간 경과, 초점 복귀만으로 재시작해서는 안 된다. 낙사와 재시작 입력이 겹치면 낙사를 우선해야 한다.
- **FR-005**: 재시작은 최초 위치·방향을 복원하고 이전 낙하·회전 움직임과 지지·점프 예약을 정리해야 한다. 안내는 제거되고 카메라는 복귀한 플레이어와 주변 섬을 즉시 보여야 하며, 무입력 상태에서는 안전한 시작 위치에 머물러야 한다.
- **FR-006**: 재시작 시 유지 중인 WASD는 현재 이동 입력으로 재개해야 하지만 탈락 중 스페이스바 입력은 지연 실행하지 않아야 한다. 점프는 해제 후 새 지상 입력을 요구해야 한다.
- **FR-007**: 초점 상실 또는 비활성화 시 수평 이동과 예약 입력을 정리해야 한다. 복귀·재활성화만으로 조작을 재실행해서는 안 되며, 이동 키 중립 및 점프·재시작 키 해제를 확인하는 기존 정책을 유지해야 한다.
- **FR-008**: 유효한 빠른 누름·해제도 한 번 처리하고 반복 활성화 후에도 한 번의 입력이 중복 실행되지 않아야 한다. 허용 조건 밖의 입력은 이후 상태에서 지연 실행하지 않아야 한다.
- **FR-009**: 리팩토링 전후에 기존 섬 배치, 플레이어 수, 조작 키, 이동·점프·낙사 설정과 탑뷰 카메라 동작을 유지해야 한다. 사용자의 기존 설정 재입력을 요구해서는 안 된다.
- **FR-010**: 변경 전후 결과를 동일한 조작·설정·검증 조건으로 비교할 수 있어야 하며, 기존 이동·점프·낙사·재시작 인수 기준을 삭제하거나 완화하여 변경을 정당화해서는 안 된다. 기존에 확인하지 못한 검수는 새로 통과한 것으로 간주해서는 안 된다.

### Key Entities *(include if feature involves data)*

- **플레이어 동작 상태**: 실제 지지 여부에 따른 지상·공중과 탈락 여부. 허용되는 조작과 전이의 기준이다.
- **입력 상태 및 요청**: 현재 이동 방향, 키 누름·해제, 처리 대기 중인 유효 요청과 초점·조작 재개 조건. 동작 상태와 동시에 성립할 수 있는 정보다.
- **시작 기준과 플레이 설정**: 최초 위치·방향, 이동 특성, 점프 높이, 낙사 경계. 변경 전후와 반복 재시작에서 유지한다.
- **플레이 피드백**: 탑뷰 시점과 탈락·재시작 안내. 현재 상태와 복귀 결과를 사용자에게 전달한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 8방향 이동·정지·방향 전환과 이동 점프에서 방향·속도 제한·카메라 추적을 모두 유지한다. 정지·이동 및 짧은·긴 누름 점프를 각각 5회 수행하여 모든 정점 높이가 기존 목표의 ±5% 이내이고 추가 점프·착지 실패는 0회다.
- **SC-002**: 낙사 경계 바로 위·동일·아래를 각각 5회 검증하여 위·동일에서 오탈락 0회, 아래에서 탈락 5회다. 탈락 중 이동·점프 입력만 수행하며 10초 관찰하는 시험 5회에서 생존 복귀는 0회다.
- **SC-003**: 실행 종료 없이 동일 플레이어로 `이동 → 점프·착지 → 낙사 → 재시작`을 20회 연속 완료한다. 매회 탈락 안내는 1초 이내 표시되고 유효 R 입력 후 2초 이내 다시 조작 가능하며, 복귀 후 첫 표시 화면에 이전 안내가 없고 중복 플레이어·시점·안내는 0개다.
- **SC-004**: 재시작 후 입력을 놓고 2초간 관찰하는 시험 10회에서 이전 움직임에 의한 재탈락·자동 점프는 0회다. WASD·스페이스바 유지 후 복귀 시험 5회에서 이동은 재개되고 자동 점프는 0회이며 해제 후 새 지상 점프는 모두 성공한다.
- **SC-005**: 생존 R, 탈락 전 R 유지, 낙사와 R 동시 입력, 요청 후 초점 상실을 각각 5회 검증하여 의도하지 않은 초기화는 0회다. 각 사례 후 탈락 상태에서 조건을 충족한 새 R 입력은 모두 한 번만 복귀시킨다.
- **SC-006**: 생존·공중·탈락 상태별 초점 전환 및 비활성화·재활성화를 각각 5회 검증하여 의도하지 않은 이동·점프·재시작은 0회다. 해제 조건 충족 후 새 입력은 모두 정상 처리한다. 활성화 전환을 20회 반복한 뒤에도 한 번의 유효 입력당 동작은 한 번이다.
- **SC-007**: 기존 네 단계의 적용 가능한 인수 기준을 100% 유지하고, 변경 전 확인된 통과 항목에 새 실패가 0건이다. 미검증 항목은 통과와 분리해 기록하며, 빠른 누름·해제와 반대 이동 키 유지 사례를 각각 5회 검증해 입력 누락·중복 실행·중립 오판정은 0회다.

## Assumptions

- 이번 작업은 기존 플레이 동작을 보존하는 내부 정리다. 새로운 조작, 글라이더, 온라인, 전투, UI 기능, 설정 화면과 조작감 튜닝은 추가하지 않는다.
- 한 명의 로컬 키보드 플레이어와 기존 섬·탑뷰 환경을 대상으로 한다. 기존 네 단계 명세 `specs/001-island-movement-camera/spec.md`부터 `specs/004-restart-after-elimination/spec.md`까지의 요구사항을 기준으로 삼고, 재시작 허용 여부 등 단계별 차이는 최신 확장 요구사항을 따른다.
- 변경 전 구현과 검증 결과를 기준선으로 기록하되, 기존 결함을 자동으로 올바른 동작으로 취급하지 않는다. 명세와 구현이 충돌하면 별도로 기록하고 이번 리팩토링에 기능 변경을 몰래 포함하지 않는다.
- 이전 단계의 미완료 수동·시각 검수는 그대로 추적한다. 이번 명세 작성은 구현 완료나 검증 통과를 의미하지 않는다.
